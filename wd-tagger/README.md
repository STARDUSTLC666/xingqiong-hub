# WD 标签反推器 · 本机架构

网页部分（选标签、拼提示词、复制）在公网就能用；**反推**需要本机跑起下面这条链路。

## 端口与职责

| 组件 | 文件 | 端口 | 职责 |
| --- | --- | --- | --- |
| UI 与同源代理 | `serve.js` | 18435 | 提供页面，并把 `/api/tag` 转发到 WD14，避开跨端口 CORS |
| WD14 ONNX 推理 | `wd14_server.py` | 18434 | 收图片二进制，返回 Danbooru 标签与置信度 |
| ComfyUI | 外部安装 | 8188 | 出图；本页只查询它是否在线 |

页面一律请求同源的 `/api/*`，不再直连 18434 —— 早期版本从 18435 跨端口打 18434 会触发 CORS 预检，这是当时反推一直失败的原因。

## 启动

```bash
node wd-tagger/serve.js
```

然后访问 `http://127.0.0.1:18435/`。后台推理进程由页面上的按钮通过 `POST /api/tagger/start` 拉起，不会因为打开页面就自动启动。

## 需要自备的文件

`wd14_server.py` 与 WD14 ONNX 模型不在本仓库内（模型体积过大）。`serve.js` 顶部的 `PYTHON`、`COMFY_DIR`、`WD_SCRIPT` 三个常量指向本机路径，换机器需要改。

## 跨域

`serve.js` 能启停本机进程并读取仓库文件，因此只对白名单来源开放跨域：站点自身的 github.io 域、`localhost`、`127.0.0.1`、`[::1]`。其它来源直接 403 —— 否则用户浏览的任意网页都能驱动这个本地服务。
